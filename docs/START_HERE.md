# V2 시작 안내

## 1. V1.5에서 전달받은 결론

V2의 첫 목적은 화면을 다시 만드는 것이 아니라, 매물 약 20만 대를 안전하게 수집하고 갱신할 수 있는 데이터 기반을 만드는 것이다.

```text
1단계  Python 수집기 + PostgreSQL
2단계  Spring Boot 검색 API
3단계  React 사용자 화면
```

초기 개발 방식은 다음과 같다.

```text
VSCode에서 직접 실행하는 Python 수집기
                 ↓
       Docker의 PostgreSQL
```

Python 수집기까지 처음부터 컨테이너에 넣지 않는다. 로컬에서 호출·파싱·저장 과정을 쉽게 확인한 뒤 안정화 단계에서 Docker로 옮긴다.

## 2. 반드시 지켜야 할 데이터 규칙

### 차량과 광고를 분리한다

목록의 광고 ID가 실제 차량 ID와 항상 같지는 않다. V1.5 조사에서 광고 ID `41464910`이 실제 차량 ID `41460716`을 가리키는 재등록 사례를 확인했다.

```text
목록의 source_listing_id
          ↓ 상세 조회
차량의 canonical_source_id 확인
          ↓
보험 · 성능 · 진단 조회
```

따라서 광고는 `vehicle_listings`, 실제 차량은 `vehicles`에 분리해 저장한다.

### 실패 시 기존 데이터를 보존한다

- 목록이 갑자기 0건이어도 기존 매물을 종료 처리하지 않는다.
- 응답 필수 필드가 사라지면 해당 수집 구간을 실패 처리한다.
- 부가 API의 404는 차량 삭제가 아니라 `NOT_AVAILABLE` 또는 재시도 상태다.
- 한 번 보이지 않은 광고를 즉시 판매 종료로 바꾸지 않는다.

### 개인정보를 수집 범위에서 제외한다

차량번호, VIN, 판매자 전화번호·주소, 자유 입력 설명 원문은 일반 서비스 DB에 저장하지 않는다. 중복 판별에 식별자가 꼭 필요해질 때만 원문 대신 HMAC 저장을 별도로 검토한다.

## 4. 바로 다음 작업

다음 한 번의 작업 범위는 아래까지만이다.

1. 지원되는 최신 Python 버전 선택 및 프로젝트 전용 가상환경 구성
